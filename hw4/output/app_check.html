Bugs the app check found, and fixed

Testing the live site the way a customer would turned up four real problems. We fixed each one and re-ran every check afterwards; all screenshots above come from the final, fixed run.

Problem foundCauseFixStatus
The chatbot answered "What hoodies do you have?" with a fallback message ("That one needs a closer look…") instead of the results page. Every model request resends the chatbot's roughly 27,000-token instructions, so a search plus its answer used about 61,000 tokens. That is just over the 60,000 per-message safety budget. Raised the per-message token budget to 150,000 in backend/agent.py. The 8-request and 12-tool-call caps still stop runaway loops. FIXED
The backend was still running code from before the latest edits. The auto-reloader had not noticed file changes in the OneDrive folder, so the server kept its 6:38 PM code. Restarted the backend and re-ran all checks against the current code. FIXED
On a 390 px phone every page could be dragged sideways (page 442 px wide). A long email address in the footer could not wrap, and the product filter row (search box + sort) did not shrink. Let footer links wrap, let footer and filter columns shrink, and hide the "Sort" label on phones. All pages now measure exactly 390 px. FIXED
A grey shadow strip showed along the right edge of the page. The closed bag drawer sat only 22 px off-screen, and its 80 px shadow reached back into view. The closed drawer is now fully hidden (visibility: hidden), which also keeps keyboard focus out of it. FIXED

How the test was run

BrowserMicrosoft Edge, driven by Playwright, as a real user: clicking the chat button, typing questions, pressing Enter, clicking cards and buttons. Desktop at 1440 × 900 (1080 tall for the check 1 close-ups), phone at 390 × 844 with touch.
Live answersNo answer was scripted or mocked. Each question went through the real backend and model, and the answers above are copied exactly from the chat, with their response times.
Database truthStock and prices were read straight from data/campus_customs.db (catalogue, inventory, orders) during the same run and compared with what the chatbot and the site showed.
Fresh sessionsEach inventory question ran in a new browser session, so no earlier conversation could help the chatbot answer.
Console errorsNone. The browser console and page errors were recorded throughout the run and the list stayed empty.
Clean-upThe test customer and everything she created were deleted afterwards, and stock was restored, so the store's data is unchanged.
